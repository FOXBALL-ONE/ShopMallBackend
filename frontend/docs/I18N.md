# 用户端国际化（i18n）

## 已支持范围

`frontend/` 使用 `@nuxtjs/i18n`，当前提供两种用户端语言：

- `en-US`（默认与回退语言）
- `zh-CN`

语言由 `pelissa_locale` Cookie 持久化，并在首次访问时根据浏览器语言检测。语言切换采用
`no_prefix` 策略，不会改变既有的商品、购物车、结账、支付回跳或订单 URL。

## 目录与职责

```text
i18n/
  i18n.config.ts                 # Vue I18n 格式化规则
  locales/
    en-US/common.ts               # 跨页面通用文案、会话与请求错误
    en-US/storefront.ts           # 用户商城共享组件与首页文案
    en-US/auth.ts                 # 登录、注册与账户验证
    en-US/catalog.ts              # 搜索、分类与商品浏览
    en-US/commerce.ts             # 购物车、结账与支付结果
    en-US/account.ts              # 账户与订单页面
    zh-CN/common.ts
    zh-CN/storefront.ts
    zh-CN/auth.ts
    zh-CN/catalog.ts
    zh-CN/commerce.ts
    zh-CN/account.ts
app/composables/useStorefrontI18n.ts
app/components/StoreLocaleSwitcher.vue
```

- 新增固定 UI 文案时，按所属领域加入 `common.ts` 或 `storefront.ts`，并同时补全两种语言。
- 组件内通过 `useStorefrontI18n()` 使用 `t`、`formatMoney`、`formatDate` 和
  `catalogCategoryName`；不要为用户可见的固定文案继续写死单一语言。
- 语言选择器放在 `StoreHeader`，账户资料页保存的 `locale` 也会同步到当前站点语言。
- 首页使用独立 Header，但同样提供 `StoreLocaleSwitcher`；不要让任何主要入口缺少语言切换能力。

当前已覆盖首页、登录与注册、搜索、分类、购物车、结账、Stripe 支付回跳、支付结果、公告列表与详情、
账户订单列表，以及共享 Header、Footer、商品卡片、购物车弹层和账户导航。其余账户与商品详情页面应继续
按业务域迁移，页面接入时同时处理 SEO、Toast、校验错误、空状态、ARIA、金额、日期和复数，不能只翻译
可见标题。

## 文案与参数规范

使用具有业务语义的点分 key，而不是直接用英文句子作 key：

```ts
const { t } = useStorefrontI18n()
t('cartPopover.removedDescription', { name: productName })
```

翻译中的参数统一使用 `{name}`、`{count}` 一类命名占位符；复数通过 Vue I18n 的 plural
语法处理，例如英文的 `'{count} item | {count} items'`。

## 金额与日期

- 商城业务和订单默认货币仍为 **USD**；`formatMoney` 只按当前语言格式化显示，不进行汇率换算。
- 后端业务时间继续以 offset-free ISO-8601 `LocalDateTime` 文本传输，例如
  `2026-08-06T19:25:14`；前端使用 `formatDate` 做本地化展示，不修改接口字段格式。

## 动态 API 内容

商品名称、商品详情、动态分类名称、公告标题和公告正文不能由前端词典硬翻。`useHttp` 会为 API
请求带上当前语言的 `Accept-Language`，后端在具备翻译数据后应据此返回本地化内容或本地化字段。

目前只对固定分类 slug 提供前端回退翻译；未知或后台新增的分类保留后端返回名称。后端尚未提供
多语言内容时，动态正文保持原样是预期行为。

## URL、SEO 与后续扩展

当前使用 `no_prefix` 是为了兼容现有外链、结账和支付回跳。若未来需要每种语言独立收录的 SEO URL，
应在完成全站页面文案迁移、生成 hreflang/canonical 策略并验证回跳链接后，再迁移为
`prefix_except_default` 或 `prefix`；不要在单个页面自行拼接 locale 前缀。

## 验证清单

```powershell
cd frontend
npm run build
```

手工验证时应确认：切换语言不会改变当前 URL；刷新后 Cookie 保持语言；`<html lang>`、共享头部、
页脚、购物车、公告、账户导航、金额和日期会随语言更新；API 请求的 `Accept-Language` 与当前语言一致。
